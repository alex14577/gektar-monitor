# Out of scope — подсистема лицензирования

Следующее явно **не реализуется** в данном эпике (YAGNI). Список зафиксирован как осознанные решения, не как упущения.

## Инфраструктура ключей

- **KMS, HSM, внешние сервисы ключей** — цель 2/10 сложности несовместима с внешними зависимостями
- **Онлайн-валидация подписи** — offline-first требование заказчика
- **Ротация ключей и механизм отзыва (revocation)** — нет инфраструктуры для инвалидации выпущенных ключей

## Привязка к окружению

- **Привязка к железу**: Machine ID, MAC-адрес, серийный номер диска — вне scope
- **Packer, anti-RE, VM-obfuscation бинаря** — XOR-обфускации достаточно для заявленных целей

## Защита от манипуляций со временем

- **Защита от тонкого отката системных часов** (сверх `iat`-floor) — требует persistent state или hardware; выходит за рамки 2/10

## UX

- **Интерактивный prompt** при отсутствии `license.key` — fail-closed, stderr + exit(1), без диалогов
- **Grace-period** при истечении или отсутствии лицензии — нет
- **GUI-визард для активации** — нет
- **Несколько одновременных лицензий** — один файл `license.key`, один ключ

## Возможности ключа

- **Feature flags / entitlements** внутри ключа — поле `lic` это только идентификатор получателя, не набор флагов
- **Количественные лимиты** (число пользователей, API-вызовов) — не предусмотрены форматом

## Связь с tradeoff

Все ограничения выше — следствие явного решения держать сложность ≤2/10. Нарушение любого пункта «out of scope» требует нового ADR и явного согласования с заказчиком.

Если потребуется масштабирование — стартовать с [[decisions/ADR-056-licensing-hmac-stateless-offline|ADR-056]] как базой и задокументировать delta-решение в новом ADR.
